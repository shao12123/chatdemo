# Chatdemo 全站规范（核对清单）

> 来源：MoreAI 对话 / 高频主题汇总的通用设定 + Figma《【25】华为项目-规范》颜色与文字四级 + 已定稿的悬停气泡 / 输入框 + 后续全站组件（提示块、错误卡片、异常恢复）。  
> 用途：本仓库任意 Chat Demo / 新 case 的合规基准。细则冲突时以本文为准；组件 Demo 与 PRD 不一致时以对应 PRD 为准。

## 0. 工作流（强制）

接到新项目 / 新 case / 优化现有 Demo 时：

1. **先对照本文逐项梳理**，不要直接改代码。
2. **列出不合规项**（缺什么、和哪条冲突、建议怎么改）。
3. **问用户是否执行修改**；用户说「修改 / 确认」后再动手。
4. 讨论阶段默认不改文件（用户明确说「先讨论不执行」时尤甚）。

参考 Demo：`conversations.html`、`高频主题汇总.html`、`三个路线方案.html`、`生成异常与恢复.html`。

## 2. AI 回复通用部件

| # | 设定 | 要求 |
|---|---|---|
| 2.1 | 发送人 | **每一条** AI 回复上方都要有 MoreAI 头像 + 名称（含首轮生成思考、跟帖、失败/暂停回复；禁止只给跟帖加、首轮漏掉）。头像动效与论文 Demo 一致（完成跳一下、眨眼、跟鼠标；断网晕眩） |
| 2.2 | 思考过程 | **必须复用路线 / 异常 Demo 同一套结构**（见下「2.2 细则」）；禁止自造扁列表 / `think-tag` 灰胶囊 |
| 2.3 | AI 操作栏 | 复制、重新生成、赞、踩、分享；赞踩互斥再点取消；点踩不弹原因 |
| 2.4 | 用户消息操作 | 复制、编辑；编辑在原位；生成中不可编辑；带文件/引用的只能复制 |
| 2.5 | 时间戳 | 悬停消息/操作栏才出现；格式：刚刚 / 今天 HH:MM / 昨天 / 周X / M月D日 / 带年份 |
| 2.6 | 目录 | 对话右边缘短横线；悬停展开列表并跳转（提问目录 / 消息目录）；与文档目录同一控件。细则见 [`对话目录-PRD.md`](../对话目录-PRD.md) / Demo [`对话目录.html`](../对话目录.html) |
| 2.7 | 流式输出 | 结构化结果边生成边出现，不要整包蹦出 |

### 2.2 思考过程细则（强制 · 曾踩坑）

**对照实现**：`三个路线方案.html` 的 `routeThinkHtml` / `routeExecIcon`；`生成异常与恢复.html` 论文思考同构。新 case **直接抄结构与 class**，不要重写一套。

| 部位 | 正确 | 禁止 |
|---|---|---|
| 头 | MoreAI 头像 + 名称；下方状态：进行中 = 当前步标题流光 + 秒数；完成 =「已完成」+ 秒数 + chevron | 只有文案、无头像；状态与路线不一致 |
| 展开区 | 白底 `.exec.paper-exec` 卡：顶栏绿色勾/转圈 +「已执行 N 个步骤」或「正在执行」 | 单独一颗灰胶囊「已执行 N 个步骤」（`.think-tag`）当主结构 |
| 步骤列表 | `.exec-list` → `.exec-item`：左侧圆点时间线（`.exec-dot`）+ `.exec-copy` 里 `span` 短标题 + `small.exec-note` 说明 | `<ol class="think-list">` / 标题与说明横排扁列表、无圆点时间线 |
| 步骤字段 | `{ t, n }`（标题 + 说明） | 自造 `{ d }` 等字段并另画 UI |
| 开合 | 默认展开；完成后自动收起；再点头可展开；收起时不渲染 body | 收起仍留扁列表；或完成态永久展开成错版样式 |
| 动效 | 进行中当前步 `.run`，其余 `.done`；完成头像跳一下后回 idle | 整包蹦出无阶段感 |

**线上截图复刻 case**：Chat 内总结文案须与截图中 MoreAI 回复一致，不增不减；只改呈现（报告卡模块），不改内容。

改 Demo / 裁独立页时：思考过程以路线案为像素级参照；自测必须展开完成态，确认是 **绿勾 + exec 卡 + 圆点时间线**，不是灰标签 + 扁列表。

### 2.9 总结报告卡 · 模块闸门

- 报告卡只渲染有数据的模块；无数据不占位、不画空壳。
- 可选模块：`verdict` / `facts` / `metrics` / `points` / `fields` / `sections` / `table` / `conclusion` / `chapters`；`tip` 在卡外、操作栏前。
- 多附件：每个文件一张独立文件卡（`file-chip`），纵向叠放。
- Excel / 台账类可出 `table` 模块；无结构材料用 `points`，少用指标格。

## 4. 交互原则

| # | 设定 | 要求 |

## 5. 颜色与文字（Figma《华为项目-规范》）

来源：[Figma 规范](https://www.figma.com/design/yqXDOTr2jDco9DVso8EVXs/?node-id=0-1)。组件不写死色值，引用 token；跟随产品浅/深色。

### 5.1 文字四级

| 级 | 透明度 | 用途 |
|---|---|---|
| 主要 | 100%（浅 #000 / 深 #FFF） | 标题、结论、正文 |
| 次要 | 60% | 副标题、说明、表头、标签（表头等靠字号字重与正文区分） |
| 占位 | 40% | 圆点、弱提示、placeholder |
| 禁用 | 20% | 禁用态 |

### 5.2 常用底与功能色（浅 / 深）

| 用途 | 浅色 | 深色 |
|---|---|---|
| 次要容器（提示块、错误卡、对比卡外层） | #EEF0F3 | #191A1D |
| 容器（块、方案块） | #FFFFFF | #111216 |
| 描边 / 弱分割 | #D8D9DD / #E3E4E7 | #434448 / #292B2E |
| 品牌 | #0A59F7 | #317AF7 |
| 成功 | #64BB5C（标签底 #E9F5E7） | #5BA854 |
| 警示 | #ED6F21 | #DB6B42 |
| 错误图标 | #E84026 | #E84026 |

规范冲突时以色阶名为准（详见行程对比 PRD 5.6）。

### 5.3 字体

- 优先：`HarmonyOS Sans SC` / `HarmonyOS Sans` / `PingFang SC` / `Noto Sans SC`
- 常用字号：15/24、14/22、13/20–21、12/18（完整字号阶梯若另有 Figma，补链后升级本文）

## 7. 输入框（已定稿）

Figma：[MoreAI 任务排队 · node 163-759](https://www.figma.com/design/dazbZcIqFzLa0n6eYdI5Co/%E3%80%9026.10.21%E3%80%91MoreAI%E4%BB%BB%E5%8A%A1%E6%8E%92%E9%98%9F?node-id=163-759)

| 属性 | 值 |
|---|---|
| 外框 | 白底；1px `#F0F0F0`；圆角 **20px**；投影 `0 2px 4px rgba(0,0,0,.04)`；内边距 12px |
| 聚焦 | 描边变为品牌色 |
| 有文件时 | 圆角可收到 16px |
| 发送默认 | 圆形品牌按钮 + 上箭头；空内容时半透明不可点 |

## 8. 全站组件

### 8.1 提示块 Tip Block

- 场景：提示 / 说明 / 注意事项 / 小贴士
- 样式：次要容器底、圆角 14、内边距 12×16×14；灯泡为块内唯一彩色
- 结构：灯泡 + 标题 → 条目「小标题：正文」；一条回复最多一个
- 不用：错误失败、方案自身风险、主结论

### 8.2 错误卡片 Error Card

- 场景：所有「生成中断 + 重试」（含断网重连中 / 已恢复 / 失败；标注修改失败等业务失败也算）
- **对照实现**：`生成异常与恢复.html` 的 `.net-wrap` / `.net-card` / `.act-primary`「重试」
- 样式：次要容器底 `#EEF0F3`（深 `#191A1D`）、**无描边**、圆角 14、垫 12×16、**与对话列 / 输入框同宽**（吃满 `.messages-inner`）；16px 圆形叉号 `#E84026` 为唯一彩色；右下蓝色主按钮「重试」+ ×
- **禁止**：白底裸文案 + 描边次按钮「重新生成」；自造红边失败框；出错仍写「重新生成」（出错用「重试」，操作栏的「重新生成」是另一套）
- 已恢复：绿色实心勾，约 1s 后收起
- × 只关卡片，关闭后不留重试入口
- 不用：用户停止、达上限（恢复提示 +「继续生成」）；文件失败（普通错误提示，无按钮）

### 8.3 异常与恢复（除 PPT）

统一接入停止 / 自动重试 / 断网重连（5×5s）/ 服务繁忙 / 内容过长 / 文件失败等；额度不足沿用线上。详见 `生成异常与恢复-PRD.md`。

## 8.4 前期刷一致性 · 曾踩坑（强制自查）

改新 Demo / 对齐旧 Demo 时，除总表外**务必扫这两条**（标注修改 case 踩过）：

| # | 坑 | 自查问句 | 正确做法 |
|---|---|---|---|
| A | MoreAI 只加在跟帖 / 失败分支，**首轮思考漏掉** | 对话里**每一段** AI 输出（含第一次「已思考」）上方有没有头像+「MoreAI」？渲染入口是否都包了（如 `hpThoughtHtml` / `routeThinkHtml` / `annoThreadHtml` / `paperThinkHtml`）？ | 每个 AI 渲染函数入口都加；不要假定「有思考文案就够了」 |
| B | 异常 UI 自造描边「重新生成」，与《生成异常与恢复》不一致 | 失败卡是不是 `.net-card` 灰底无描边？按钮是不是主色「重试」？有没有圆形叉号？ | 直接抄异常 Demo 的 Error Card；业务失败也走同一套，禁止另起一套失败条 |

核对清单输出时，这两项不合规要单独列出来问用户。

## 9. 交付习惯

- 先讨论、用户说「修改」再改
- 需要给 AGENT 开发时：PRD MD + HTML（可复制 MD、下载、新开 Demo）
- 上传：用户明确要求后再 commit / push；先 `git pull --ff-only`；同步 origin / codeup / cursor
- 版本：改 Demo 后更新 `version.json`
