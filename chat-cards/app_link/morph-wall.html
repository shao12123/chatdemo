V1 · 待授权 askcanonical

未连接：主按钮「授权」。点击后由 host 打开授权弹层（同意 → V2；关窗 → V4）。

范围：本墙只画 chat 内 .link。授权弹层 #authMask / .auth-go 属 host overlay，写在 Tool 回调约定里，不做 V 面板。
payload：app{id,name,icon,desc} · state: ask|linked|failed|cancelled。

V2 · 已连接 linked状态

名称后出现品牌色对勾；按钮换成次级「管理」（描边）。一张卡一个主按钮：此态无主按钮。

授权成功后同一张卡原地从 ask 转 linked（lead 文案也换成已连接版）。

V3 · 连接失败 failed异常

卡外观与待授权一致，按钮仍叫「授权」，点击重新走授权。失败原因写在 lead，不另出错误卡。

.link-fail 红字样式在源里保留但当前 demo 未使用；若要卡内标红须另评审。与 error_card 的关系：连接失败可选择只改 lead，不强制接 net-card。

V4 · 已取消 cancelled状态

用户关掉授权窗：卡回到可再授权，lead 说明「还没连上」。

与 V1 的差别只在 lead 文案与 state；视觉同 ask。
