V1 · 诊断 + 方案canonical

论文修订 Demo：lead → 问题 / 原因两栏 → 最终方案（「被选用」）+ 过程方案折叠（默认收起）→ 选用理由 →「这一版会改」标签。可点「过程方案」开合。

范围：仅 .revise-card。字段：lead · problem · cause · plans[]（首项=被选用）· reason · chips[]。折叠只改展示，不改已选方案；卡内无主按钮 / 多选确认。
边界：① 思考过程（执行步骤折叠）不是本卡；② 点「再生成一版」前的 .pick-card「对哪里不满意」不是本卡，属于补输入 → 归 ask_form（host_only，pick 为其单选壳的遗留写法）；③ 不并入 doc_summary。

V2 · 方案型no problem / cause

推荐方案（被选用）→ 备选（可折）→ 选用理由。无「问题 / 原因」栏；或只留一栏时用 .revise-grid.single。

2a · 无 grid（只有方案 + 理由）

2b · .revise-grid.single（只有「问题」一栏，无「原因」）

渲染规则（同源 reviseStreamHtml）：problem || cause 有值才出 grid；cause 为空 → 加 .single。

V3 · 边界型能说 / 不能说

同一 .revise-card 壳，文案换成「能说什么 / 不能说什么」→ 建议措辞 → 行动范围。用于风险裁剪、口径、合规类回复。

V3 是文案变体：CSS 不新增类；左右栏仍复用 .revise-cell（标签 span 改为「能说什么 / 不能说什么」）。「建议措辞」复用 .revise-plan 行，不出「被选用」角标。

V4 · 无「这一版会改」chips 可选

非改稿场景（只做判断，不绑定改动范围）：chips 为 null 时整个模块不渲染（有数据才渲染）。

验收（源 Demo）：「本版改动范围（有则必须有）」。无改动范围时不要用空 chips 占位；也不要塞通用空话凑模块。

V5 · 过程方案展开.plans.open

展开后：被选用方案在上（带角标），过程方案按行列出、无角标，可与已选用区分。再点「收起过程方案」恢复。

V6 · 深色theme-dark

点顶栏「深色」切换整页（V6 为深色验收面板）。conversations.html 现无 .revise-* 深色规则，本墙补了一套 token。

深色 token（墙内定义）：cell #25272b · 分割线 #3a3c41 · 次文 rgba(255,255,255,.6) · 被选用角标 #12301f / #5ba854 · chip #111216 / #8fb0ff。上线前需并回主页 html.theme-dark。
